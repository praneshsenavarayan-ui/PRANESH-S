About the project

A full development team, compressed into six cooperating agents

DevPilot X was built for the IBM Bob 2.0 Hackathon to attack a problem every engineering team feels: the gap between writing code and shipping it safely. Instead of one general-purpose assistant, DevPilot X runs a coordinated crew of specialists — each one focused on a single stage of the lifecycle, handing work to the next agent the way a real team would.

End-to-end automation

From task planning to code review, every stage runs without manual hand-off.

Built on IBM Bob 2.0

The orchestration layer routes context between agents and keeps state consistent across a run.

Explainable at every step

Each agent logs its reasoning, so reviewers can audit a fix instead of just trusting it.

The multi-agent workflow

One request enters the orchestrator. Six specialized agents pick it up in sequence, each contributing a distinct capability before the change reaches your pull request.

01

Planner Agent

Breaks a feature request or issue into an ordered set of concrete engineering tasks.

02

→
03

Debug Agent

Runs the suite, isolates failing traces, and proposes a targeted patch for each defect.

→

→
05

Doc Agent

Produces readable documentation and inline comments straight from the diff.

→
06

Review Agent

Scores maintainability and risk, then opens the pull request with a full changelog.

The Doc Agent reads the diff, not just the function signature — so the docs describe what actually changed.

retry_policy.py+18 −3
def retry_with_backoff(fn, retries=3, base_delay=0.5):
    # Retries fn with exponential backoff
    for attempt in range(retries):
        try:
            return fn()
        except TransientError as e:
            wait = base_delay * (2 ** attempt)
            time.sleep(wait)
    raise MaxRetriesExceeded()

How we built it

Project workflow timeline

From problem statement to a working demo, in six phases across the hackathon sprint.

1
Phase 1

Problem framing

Interviewed developers about where review and documentation debt actually comes from, and scoped the six-agent split.

2
Phase 2

Architecture on IBM Bob 2.0

Designed the orchestration layer that routes tasks between agents and persists shared context for a run.

3
Phase 3

Agent development

Built and tuned the Planner, Code, Debug, Test, Doc and Review agents against a shared benchmark repo.

4
Phase 4

Integration & testing

Wired the agents into a single pipeline and stress-tested it against real open-source pull requests.

5
Phase 5

Dashboard & UI

Built the live telemetry dashboard, chat assistant and analytics views shown in this demo.

6
Phase 6

Demo & submission

Packaged the build, rehearsed the walkthrough, and submitted for the national hackathon round.

What's next

Future scope

DevPilot X is a hackathon-stage build. Here's where the roadmap goes from here.

VS Code & JetBrains plugin

Bring the six agents into the editor, with inline suggestions instead of a separate dashboard.

CI/CD pipeline integration

Trigger the agent pipeline automatically on every pull request, gated by the quality score.

On-prem & watsonx.ai deployment

Package the orchestrator for private cloud deployments where source code can't leave the network.

Multi-language expansion

Extend beyond the current language set to cover Go, Rust and mobile codebases.

Autonomous pull requests

Let the agent crew open, describe and self-merge low-risk fixes with human approval gates.

Security vulnerability agent

A seventh agent focused solely on dependency CVEs and injection-class vulnerabilities.
